# EasyVtuber 移动端可行性与算力压缩技术报告

## 背景
EasyVtuber 当前的启动器、OBS/Spout 输出、依赖和模型部署流程均围绕 Windows 桌面 GPU（CUDA/TensorRT/DirectML）设计。要在手机端跑通，需要同时解决「模型压缩 + 移植管线 + 移动端硬件利用」三方面问题。本报告给出算力目标、压缩思路和迁移路线，帮助评估可行性。

## 现状与瓶颈
- **模型栈**：THA3/THA4 主渲染模型 + （可选）RIFE 插帧 + （可选）waifu2x/Real-ESRGAN 超分。默认 PC 路径基于 FP16/FP32，分辨率 512→720/1080。
- **依赖链**：Python + onnxruntime-gpu/TensorRT/DirectML、Spout/OBS 输出、iFacialMocap/OSF 输入，均未提供移动端 UI/输出适配。
- **算力消耗**：主渲染模型为绝对主力；插帧/超分在手机上基本不可用（显存和带宽都不足）。

## 移动端可行性判断
- **能否跑通**：可以做验证性移植，但需重写推理管线（onnxruntime-mobile、ncnn、TFLite 任选其一），并放弃插帧/超分，使用轻量模型和低分辨率。
- **目标帧率与算力**：
  - 轻量配置（无插帧/超分，输入 256～320，输出 ≤720p，FP16/INT8）：约 1～2 GFLOPs/帧，对应 15～30fps 需要 ~4～10 TOPS（INT8）移动 NPU/GPU 峰值。
  - 中等配置（输入 320～384，输出 720p，保持半精度）：约 2～3 GFLOPs/帧，20fps 需 ~8～12 TOPS；30fps 需 ~12～18 TOPS，部分高端旗舰才有余量。
  - 高画质（>1080p 或插帧/超分）：基本不推荐，手机显存/带宽/散热难以支撑。
- **功耗与散热**：即便算力足够，连续直播会受 SoC 降频限制，需动态降帧/降分辨率。

## 推荐压缩与裁剪策略
1. **模型选择**：优先 THA `v3_seperable_half` 或 `v4_student`；禁用 RIFE 插帧与超分模块。
2. **分辨率控制**：输入裁剪在 256～320；输出上限 720p。必要时进一步降到 480p 以稳帧。
3. **量化与裁剪**：
   - 基于 `ezvtuber-rt` 的 ONNX 模型做 FP16 或 INT8 量化；对模型的眉毛/身体通道可裁剪以减小算子数和内存。
   - 目标：权重体积 <100MB、激活内存峰值 <300MB，单帧 FLOPs 控制在 1～2 GFLOPs。
4. **算子/框架适配**：优先选 onnxruntime-mobile（NNAPI/MPS/DirectML-mobile）、ncnn（Vulkan）、TFLite（GPU Delegate）。需逐算子验证精度。
5. **缓存与调度**：沿用姿态缓存思想，在移动端增加「姿态未变时跳过推理」的快速路径；必要时动态锁帧到 20fps。

## 迁移落地步骤（建议顺序）
1. **模型侧**：从 `ezvtuber-rt` 导出 ONNX → 做 FP16/INT8 量化 → 裁剪多余输出通道 → 静态输入尺寸 256～320。
2. **推理侧**：选定移动框架（onnxruntime-mobile/ncnn/TFLite），搭建最小 demo（单图推理），验证算子兼容与吞吐。
3. **输入侧**：替换 iFacialMocap/OSF，改为手机摄像头 + MediaPipe/ARKit/ARCore 取姿态；统一姿态向量接口。
4. **输出侧**：移除 OBS/Spout，改为纹理/Surface 直接渲染；可选 WebRTC/RTMP 推流。
5. **性能验证**：在 4～6 TOPS 和 8～10 TOPS 设备上实测 256/320 输入、720p 输出的帧率与功耗，微调分辨率与锁帧策略。

## 风险与权衡
- **画质/帧率取舍**：禁用插帧与超分后，画质与流畅度低于 PC；需用户接受。
- **精度回退**：INT8 可能带来嘴型/表情失真，需逐场景对比；不通过则退回 FP16。
- **算子缺失**：部分移动后端不支持特定算子/reshape 路径，可能需要重新导出或手写算子。
- **散热/降频**：长时间直播可能触发 SoC 降频，需监控温度并动态降帧。

## 结论
- 在手机上跑通「基础渲染模型 + 低分辨率 + 无插帧/超分」是可行的，但需要模型量化/裁剪和完整的管线重写。
- 目标配置建议：`v3_seperable_half`/`v4_student`，输入 256～320，输出 ≤720p，FP16 或 INT8，单帧 1～2 GFLOPs；期望 15～30fps 需 4～10 TOPS（INT8）移动端峰值算力。
- 想要接近 PC 体验（高帧率/高分辨率/超分）在当前移动端受限明显，仍以 PC 端为主力方案。
